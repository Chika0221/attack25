# ATTACK 25 — リアルタイム早押しクイズ進行システム

テレビ番組「アタック25」形式のクイズ大会を、**ブラウザだけ**で運営できる Web アプリです。
5×5＝25枚のパネルをオセロのルールで奪い合いながら、早押しクイズを進行できます。

### 🔗 本番環境（デプロイ済み）

| 役割 | URL |
| --- | --- |
| **ボード画面**（観客・プロジェクター） | <https://attack-game.onrender.com/> |
| **司会者画面**（アドミン） | <https://attack-game.onrender.com/admin> |
| **参加者画面**（スマホ） | <https://attack-game.onrender.com/player> |

インストール不要・アカウント不要で、この3つの URL を開くだけで大会が始められます。

- **司会者**はブラウザからパネル・問題・解答・早押しをすべて操作
- **参加者**は自分のスマホで「BUZZ」ボタンを押すだけ
- **観客／プロジェクター**には16:9のボード画面を映すだけ

すべての画面は Socket.IO でリアルタイムに同期されます。

> 🚨 **使い始める前に、必ずサーバを起動（ウォームアップ）してください。**
> 無料プランのため 15分アクセスがないとサーバが停止しており、**そのまま参加者に URL を配ると全員が数十秒〜1分ほど待たされます。**
> → [使う前にサーバを起こす（必須）](#使う前にサーバを起こす必須)

## 使う前にサーバを起こす（必須）

このアプリは **Render の無料プラン** で動いています。無料プランは **15分間アクセスがないとサーバが自動停止**し、
次に誰かがアクセスした瞬間に起動を開始します。**起動には数十秒〜1分ほどかかります。**

そのため、**参加者に URL を配る前に、司会者が先にサーバを起こしておいてください。**

### 手順

```
1. 大会が始まる 5〜10分前に、司会者が
   → https://attack-game.onrender.com/
   をブラウザで開く

2. 真っ白な画面 or 読み込み中のままでも、そのまま閉じずに待つ（最大1分ほど）

3. 黒背景に「ATTACK 25」と 25枚のパネル、右側に RED/GREEN/WHITE/BLUE の
   数字が表示されたら起動完了 ✅

4. ヘッダーに「問題読み上げ待機中...」と出ていることを確認

5. ここまで来てから、参加者に /player の URL（QR）を配る
```

### 起動できたかをコマンドで確認する場合

```bash
# 200 が返り、time が数秒以内なら起動済み
curl -s -o /dev/null -w "status=%{http_code} time=%{time_total}s\n" https://attack-game.onrender.com/
```

初回（スリープ復帰）は `time` が 30〜60秒 になることがあります。2回目以降が 1秒以内なら準備完了です。

### やってはいけないこと

- ❌ **起こさずに参加者へ URL を配る** … 参加者全員が真っ白な画面で待つことになり、「壊れている」と誤解されます
- ❌ **試合の途中で15分以上放置する** … スリープすると **盤面・参加者・出題中の問題がすべて消えます**（ゲーム状態はメモリ保持のため）。休憩を挟むときは誰か1人が画面を開いたままにしておいてください
- ❌ **本番中に `main` へ push する** … 再デプロイが走り、接続が切れて盤面がリセットされます

> 💡 進行中は司会者画面とボード画面が常に通信しているため、試合中に勝手にスリープすることはありません。**気をつけるのは「開始前」と「長い休憩」だけです。**

## 3つの画面

| 役割 | パス | 誰が見るか | 用途 |
| --- | --- | --- | --- |
| **ボード画面** | `/` | 観客・プロジェクター | 25枚のパネル、各色の枚数、問題文・解答、早押しした人の表示 |
| **司会者画面** | `/admin` | 司会者・スタッフ | パネル操作、問題出題、正解／不正解判定、早押しリセット |
| **参加者画面** | `/player` | 解答者（最大4人） | 名前の入力と早押しボタン |

推奨構成:

```
┌────────────────────────────┐
│  プロジェクター / 大画面       │ → https://attack-game.onrender.com/
└────────────────────────────┘
┌────────────────────────────┐
│  司会者のPC（手元）           │ → https://attack-game.onrender.com/admin
└────────────────────────────┘
┌────────────────────────────┐
│  参加者のスマホ ×4            │ → https://attack-game.onrender.com/player
└────────────────────────────┘
```

**効果音はボード画面（`/`）でのみ再生されます。** スピーカーは大画面側のPCに繋いでください。

## 管理者（アドミン）画面の出し方

**ブラウザで下の URL を開くだけです。ログインもパスワードもありません。**

```
https://attack-game.onrender.com/admin
```

司会者画面は次の4ブロックで構成されています。

### 1. 早押し・プレイヤー状態（`BuzzerManager`）

- 誰かが BUZZ を押すと **「解答者: ○○」** が表示され、他の参加者のボタンは自動でロックされます
- **「正解 (〇)」** … 全クライアントに `correctAnswer` を通知します
- **「不正解 (×)」** … 全クライアントに `wrongAnswer` を通知し、ボード画面で `but.mp3` が鳴ります
- **「解答終了（待機状態に戻す）」** … 早押しロックを解除して次の問題へ
- **「プレイヤーをリセット」**（右上のリンク） … 全参加者を強制退出させ、色の割り当てを開放します

### 2. 操作する色を選択 ＋ 強制上書きモード

- `赤 / 緑 / 白 / 青 / 空` から現在操作する色を選びます（初期値は赤）
- **強制上書きモード** にチェックを入れると、オセロの挟み判定を無視して、クリックしたマスだけを選択色に塗れます（誤操作の修正や、初期配置の準備に便利）

### 3. パネル操作（`AdminPanelBoard`）

- 5×5 のマスをクリックすると、選択中の色でパネルを取得します
- 通常モードではオセロの挟み判定が働き、**0.6秒ごとに1枚ずつ** 順番にひっくり返るアニメーションがボード画面に反映されます
- アニメーション中は誤操作防止のため、クリックが無効になります
- 既にパネルが置かれているマスを通常モードでクリックすると警告が出ます
- **「盤面をリセット」**（右上のリンク）で 25 枚すべてを空に戻します

### 4. 問題・解答管理（`QuestionManager`）

- 「問題文」「解答」を入力し **「問題を表示」** → ボード画面の中央に問題が出ます（解答は隠れたまま）
- **「解答を表示」** → 問題の下に緑色で解答が表示されます
- **「クリア」** → 問題ボックスをボード画面から消します

> ⚠️ **`/admin` は誰でも開けます。** 認証がないため、URL を知っている参加者や観客が盤面・問題・正誤判定を操作できてしまいます。参加者には `/player` の URL だけを伝え、`/admin` は共有しないでください。厳密に守りたい場合は [既知の制限](#既知の制限注意点) を参照してください。

## 参加者をオンラインで集める方法

### 本番環境（通常はこれだけ）

参加者に次の URL を共有します。**同じ Wi-Fi に繋ぐ必要はなく、それぞれのモバイル回線からでも参加できます。**

```
https://attack-game.onrender.com/player
```

名前を入れて「参加する」を押すと、**先着4名まで**参加でき、参加順に `赤 → 緑 → 白 → 青` の色が自動で割り当てられます。5人目には「すでに4名参加しているため、これ以上参加できません。」と表示されます。

QR コードにしておくと当日の案内が速くなります。

```bash
# 例: qrencode で印刷用のQRを作る
qrencode -o player-qr.png "https://attack-game.onrender.com/player"
```

配布時の注意:

- **スリープからの復帰待ちがあります。** 参加者に配る前に、司会者が先にボード画面を開いてサーバを起こしておいてください
- **参加者がページを再読み込みしたりスマホがスリープすると退室扱い**になり、色が開放されます。再参加すると空いている色に入り直すため、色が変わることがあります
- 参加者を入れ替えるときは `/admin` の「プレイヤーをリセット」で全員を退出させると、色の並びがきれいに戻ります

### オフライン会場・回線が不安な会場で使う場合（LAN 運用）

インターネットが使えない、または遅延を最小にしたい場合は、会場のPCでサーバを立てて同じ Wi-Fi から繋ぐ運用もできます（[ローカルでの開発](#ローカルでの開発)の手順で起動）。サーバは既定で `0.0.0.0` を待ち受けているため追加設定は不要です。

```bash
# サーバ機のIPアドレスを調べる
hostname -I          # Linux
ipconfig             # Windows

# 参加者に伝えるURL（例）
# http://192.168.1.20:3000/player
```

繋がらないときはファイアウォールでポートを開けてください。

```bash
sudo ufw allow 3000/tcp
```

一時的にインターネット越しへ公開したいだけなら、トンネルも使えます（WebSocket 対応のものを選んでください）。

```bash
cloudflared tunnel --url http://localhost:3000   # Cloudflare Tunnel
ngrok http 3000                                  # ngrok
```

## 得点（パネル枚数）の出し方・計算ルール

### 表示方法

ボード画面（`/`）の右側に **RED / GREEN / WHITE / BLUE** の枚数が常に大きく表示されます。
これは司会者が操作した盤面から**自動計算**されるもので、点数を手入力する場所はありません。

```ts
// app/page.tsx — 盤面の色を数えているだけ
const counts = {
  red:   board.filter(c => c === 1).length,
  green: board.filter(c => c === 2).length,
  white: board.filter(c => c === 3).length,
  blue:  board.filter(c => c === 4).length,
};
```

つまり **「そのチームが今持っているパネルの枚数」＝ 得点** です。盤面を操作すれば即座に全画面へ反映されます。

### パネルの色コード

| 値 | 色 | 参加順 |
| --- | --- | --- |
| `0` | 空（未取得） | — |
| `1` | 赤 | 1人目 |
| `2` | 緑 | 2人目 |
| `3` | 白 | 3人目 |
| `4` | 青 | 4人目 |

盤面は長さ 25 の一次元配列で、`index = y * 5 + x`（左上が 0、右下が 24）。画面上のマスには `index + 1` の番号（1〜25）が表示されます。

### 挟み判定（オセロロジック）

`app/lib/gameLogic.ts` の `getFlippablePanels()` が担当します。

- 空きマスにのみパネルを置けます
- 置いたマスから **8方向**（縦・横・斜め）を探索します
- 「相手色が1枚以上続き、その先に自分の色がある」方向だけ、間に挟まれた相手色をすべて自分の色に変えます
- 途中に空きマスがある方向、盤外に出る方向は無効です

例（`●`=自分、`○`=相手、`・`=空、★の位置に置く）:

```
★ ○ ○ ●   →   ● ● ● ●    （挟めるので2枚ひっくり返る）
★ ○ ・ ●   →   ● ○ ・ ●    （空きマスがあるので何も返らない）
```

ひっくり返るパネルは 0.6 秒間隔で1枚ずつサーバに送信されるため、大画面では順番にめくれる演出になります。

### 手動で枚数を調整したいとき

挟み判定を通したくない場合（ルール上の例外処理、初期パネルの配置、誤操作の修正など）は、司会者画面の **強制上書きモード** を使ってください。クリックしたマスだけを選択色（`空` を含む）に直接書き換えられます。

```
【準備】
 1. 開始10分前に https://attack-game.onrender.com/ を開く（スリープ解除）
 2. 大画面に全画面表示、スピーカーの音出しを確認

【1問ごとのループ】

 9. 司会者が問題を読み上げる
10. 参加者が BUZZ を押す      → 最速の1人だけがロックを取得
                              → 大画面ヘッダーがその人の色に変わり、色別の効果音が鳴る
11. 「正解 (〇)」/「不正解 (×)」を押して判定
                              → 不正解時は but.mp3 が鳴る
12. 「解答を表示」で答え合わせ（任意）
13. 正解者の色を選択 → パネルをクリックして取得（オセロ判定でひっくり返る）
14. 「解答終了（待機状態に戻す）」で早押しを解除
15. 「クリア」で問題ボックスを消して 7 に戻る

【終了】
16. 右側の枚数表示で勝敗を確認
17. 次のゲームへ行く場合は「盤面をリセット」＋「プレイヤーをリセット」
```

## 問題リスト（JSON）のインポート

司会者画面の「問題リスト」から JSON ファイルを読み込めます。読み込んだリストは**司会者のブラウザの localStorage**（キー: `attack25_questions`）に保存されるため、ページを再読み込みしても、サーバがスリープしても残ります。

### フォーマット

トップレベルが配列であることが必須です。`question`/`answer` の代わりに短縮キー `q`/`a` も使えます。

```json
[
  { "question": "日本で一番高い山は？", "answer": "富士山" },
  { "question": "1+1は？", "answer": "2" },
  { "q": "短縮キーでも読み込めます", "a": "OK" }
]
```

### 使い方

1. **「JSONをインポート」** をクリックしてファイルを選択（既存リストに**追記**されます）
2. リストの項目をクリックすると、問題文・解答が入力欄に流し込まれます
3. あとは「問題を表示」→「解答を表示」で進行します
4. 個別削除は各行の `✕`、全消しは **「リストクリア」**

> 問題リストはサーバに保存されず、**司会者のブラウザにのみ**残ります。司会者PCを変えるとき・シークレットウィンドウを使うときは JSON ファイルを持ち歩いてください。

### AI に問題を作らせるプロンプト例

問題づくりは AI に任せると一気に楽になります。以下をコピペして、生成された JSON を `.json` ファイルに保存し、「JSONをインポート」で読み込んでください。

#### 1. 基本（そのままコピペ）

```text
クイズ大会用の問題を JSON 配列で25問作ってください。

【出力形式】
- 説明文やコードブロックは書かず、JSON配列だけを出力してください
- 各要素は {"question": "問題文", "answer": "解答"} の形式

【問題文のルール】
- 司会者が声に出して読み上げます。1文〜2文、80文字以内にしてください
- 「次のうちどれ？」のような選択肢形式は使わないでください（選択肢を表示できません）
- 早押しなので、最後まで聞かなくても答えが絞れる文にしてください

【解答のルール】
- 20文字以内の短い単語・固有名詞にしてください
- 表記揺れが起きやすいものは避けてください（読み方が1つに定まるもの）

【内容のルール】
- 難易度は中学生〜高校生レベル
- 事実として確実に正しいものだけにしてください。自信がないものは入れないでください
- 年号や統計など、時間が経つと答えが変わるものは避けてください
```

#### 2. ジャンル・難易度を指定する

```text
クイズ大会用の問題を JSON 配列で30問作ってください。
出力は JSON 配列のみ。各要素は {"question": "...", "answer": "..."} の形式です。

【ジャンル配分】
- 理科・科学: 8問
- 日本史・世界史: 6問
- 地理: 6問
- スポーツ: 5問
- サブカルチャー（アニメ・ゲーム・音楽）: 5問

【難易度配分】
- 誰でも答えられる易しい問題: 10問
- 少し考える標準問題: 15問
- 難問: 5問
- 配列の先頭から易しい順に並べてください

【制約】
- 問題文は80文字以内、読み上げ用の自然な日本語
- 解答は20文字以内
- 事実として確実に正しいものだけ
```

#### 3. 参加者に合わせて寄せる

```text
大学のサークルの新歓イベント用にクイズを20問、JSON配列で作ってください。
出力は JSON 配列のみ。各要素は {"question": "...", "answer": "..."} の形式です。

- 参加者は大学1年生です。10代後半〜20代前半が分かる話題を中心に
- 半分は「知らなくても勘で当てられる」易しい問題にして、盛り上がるようにしてください
- 特定の人が有利になりすぎる専門的な問題は入れないでください
- 問題文は80文字以内、解答は20文字以内
```

#### 4. 既存のリストに足す（重複させない）

```text
以下は既に用意済みのクイズ問題です。

<既存の問題>
（ここに手持ちの JSON をそのまま貼る）
</既存の問題>

これと**題材が重複しない**問題を追加で15問、JSON配列で作ってください。
出力は追加分の JSON 配列のみ。各要素は {"question": "...", "answer": "..."} の形式です。
既存の問題と同じ答えになるもの、言い換えただけのものは除いてください。
問題文は80文字以内、解答は20文字以内、事実として確実に正しいものだけにしてください。
```

#### プロンプトを書くときのコツ

| ポイント | 理由 |
| --- | --- |
| **「JSON配列のみ出力」と明示する** | 前置きや ```json のフェンスが付くとインポートに失敗します（付いてきたら手で削ってください） |
| **解答は20文字以内** | 司会者画面の解答欄が1行の入力欄で、ボード画面でも大きく表示されるため |
| **問題文は80文字以内** | 読み上げ用。長いと早押しのテンポが崩れ、ボード画面の問題ボックスからも溢れます |
| **選択肢形式を禁止する** | このアプリに選択肢を表示する機能はありません |
| **「事実として確実に正しいものだけ」と書く** | それでも AI は間違えます。**本番前に人間が必ず全問チェックしてください** |
| **年号・最新統計を避けさせる** | 「現在の世界一は？」のような問題は時間が経つと答えが変わります |

#### 生成後の検証

インポートする前に形式をチェックしておくと安心です。

```bash
# 配列であり、全要素に question / answer があるか
jq -e 'type == "array" and all(.[]; has("question") and has("answer"))' questions.json > /dev/null \
  && echo "形式OK ($(jq length questions.json)問)"

# 解答が長すぎるものを洗い出す
jq -r '.[] | select((.answer | length) > 20) | "長い解答: \(.answer)"' questions.json

# 解答の重複チェック
jq -r '[.[].answer] | group_by(.) | map(select(length > 1) | .[0]) | .[]' questions.json
```

#### （応用）Claude API でまとめて生成する

手作業を挟まずに JSON を得たい場合は、構造化出力を使うと形式が保証されます（このリポジトリと同じ TypeScript の例）。

```bash
npm install @anthropic-ai/sdk zod
export ANTHROPIC_API_KEY=sk-ant-...
```

```typescript
// scripts/generate-questions.ts
import Anthropic from "@anthropic-ai/sdk";
import { z } from "zod";
import { zodOutputFormat } from "@anthropic-ai/sdk/helpers/zod";
import fs from "fs";

const QuestionList = z.object({
  questions: z.array(
    z.object({
      question: z.string().describe("読み上げ用の問題文。80文字以内"),
      answer: z.string().describe("解答。20文字以内の短い語"),
    }),
  ),
});

const client = new Anthropic();

// Claude Opus 5 は既定で思考しながら回答します
const response = await client.messages.parse({
  model: "claude-opus-5",
  max_tokens: 16000,
  messages: [
    {
      role: "user",
      content: `早押しクイズ大会用の問題を25問作ってください。
難易度は中学生〜高校生レベル。ジャンルは理科・歴史・地理・スポーツ・サブカルを均等に。
問題文は司会者が読み上げるので80文字以内、解答は20文字以内の短い語にしてください。
選択肢形式は使わず、事実として確実に正しいものだけにしてください。`,
    },
  ],
  output_config: { format: zodOutputFormat(QuestionList) },
});

// アプリが読む形（配列そのもの）に整えて保存
fs.writeFileSync(
  "questions.json",
  JSON.stringify(response.parsed_output!.questions, null, 2),
);
```

出力された `questions.json` を司会者画面の「JSONをインポート」で読み込めばそのまま使えます。
**AI が作った問題は必ず人間が検算してから本番に出してください。**

## デプロイと運用（Render・無料プラン）

本番は **Render の Web Service（Free プラン）** として <https://attack-game.onrender.com> にデプロイされています。
`main` ブランチへ push すると自動でビルド・再デプロイされます。

### サービス設定

| 項目 | 値 |
| --- | --- |
| Environment | Node |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm start`（= `NODE_ENV=production node server.js`） |
| Instances | **1（必須）** |
| Health Check Path | `/` |

- **ポートは Render が `PORT` 環境変数で注入**し、`server.js` がそれを読みます。手動設定は不要です
- `HOSTNAME` は既定の `0.0.0.0` のままにしてください
- WebSocket は Render 標準でそのまま通ります。追加設定は不要です
- `next start` ではなく `node server.js` を使う必要があります（Socket.IO サーバを内包しているため）

### ⚠️ インスタンスは必ず1つに

ゲーム状態は `server.js` のメモリに1組だけ持っています。インスタンスを2つ以上に増やすと、
**司会者と参加者が別インスタンスに振り分けられて盤面が同期しなくなります**。
スケールアウトしたい場合は Redis アダプタ（`@socket.io/redis-adapter`）などで状態を外部化する改修が必要です。

### ⚠️ 無料プランのスリープ（運用上いちばん大事）

- **15分間アクセスがないとサーバが停止**し、次のアクセス時に起動します（初回表示に数十秒〜1分）
- 起動待ちの間、参加者の画面は真っ白または接続待ちのままになります → **必ず司会者が先に起こしてから URL を配る**（→ [使う前にサーバを起こす](#使う前にサーバを起こす必須)）
- **スリープ・再デプロイでゲーム状態（盤面・参加者・出題中の問題）は初期化されます。** 試合の途中で15分以上中断しないでください
- 外部の監視サービス（UptimeRobot 等）で定期 ping を打って起こし続ける手もありますが、**無料プランの稼働時間（月750時間）を消費し切る**ため、常時 ping はおすすめしません。開催前に手動で起こすのが現実的です
- スリープを完全になくしたい場合は Render の有料プラン（Starter 以上）へ移行してください

### 手動での再デプロイ・復旧

Render のダッシュボードから **Manual Deploy → Deploy latest commit**、または問題が起きたときは **Restart service** で復帰できます（盤面はリセットされます）。

## 仕様リファレンス

### サーバが保持するゲーム状態

`server.js` のメモリ上に1組だけ存在し、接続時と更新時に全クライアントへブロードキャストされます。

```js
{
  buzzerLocked: false,        // 早押しがロックされているか
  buzzedPlayer: null,         // 早押しに成功したプレイヤー名
  board: Array(25).fill(0),   // 5x5の盤面（0:空, 1:赤, 2:緑, 3:白, 4:青）
  players: [],                // [{ id: socket.id, name, color }]
  questionText: "",           // 大画面に出す問題文
  answerText: "",             // 解答文
  showAnswer: false,          // 解答を表示中か
}
```

### Socket.IO イベント

クライアントは `app/lib/socketClient.ts` で **同一オリジン**に接続します（本番なら `https://attack-game.onrender.com`）。接続先の URL をコードに書く必要はありません。

**クライアント → サーバ**

| イベント | 送信元 | ペイロード | 動作 |
| --- | --- | --- | --- |
| `join` | player | `name`, callback | 参加。成功時 `{ success: true, color }` を返す。満席（4人）／二重参加は `{ success: false, message }` |
| `buzz` | player | `playerName` | 未ロックなら先着1名がロックを獲得 |
| `leave` | player | — | 自主退出（色を開放） |
| `resetBuzzer` | admin | — | 早押しロックを解除 |
| `resetPlayers` | admin | — | 全プレイヤーを削除し、`forceLeave` を全員に通知 |
| `correctAnswer` | admin | — | 全クライアントへ `correctAnswer` を中継 |
| `wrongAnswer` | admin | — | 全クライアントへ `wrongAnswer` を中継（`but.mp3`） |
| `updateQuestion` | admin | `{ questionText?, answerText?, showAnswer? }` | 指定されたフィールドだけを更新 |
| `updateBoard` | admin | `number[25]` | 盤面を丸ごと置き換え |

**サーバ → クライアント**

| イベント | ペイロード | 用途 |
| --- | --- | --- |
| `gameState` | 上記の状態オブジェクト | 全画面の再描画 |
| `correctAnswer` | — | 正解演出用（現状ボード画面では未使用） |
| `wrongAnswer` | — | ボード画面で `but.mp3` を再生 |
| `forceLeave` | — | 参加者画面を名前入力画面に戻す |

切断（`disconnect`）時は自動でそのプレイヤーが `players` から削除され、色が開放されます。

## 既知の制限・注意点

- **`/admin` に認証がありません。** 本番 URL は公開されているため、`https://attack-game.onrender.com/admin` を開いた人は誰でも盤面・問題・正誤判定を操作できます。参加者には `/player` だけを伝えてください。厳密に守る必要がある場合は、`server.js` に管理者用トークンの検証を入れる、Cloudflare Access などを前段に置く、といった改修が必要です。
- **ゲーム状態はメモリのみ。** サーバの再起動・再デプロイ・無料プランのスリープで、盤面・参加者・出題中の問題がすべて初期化されます（問題リストだけは司会者ブラウザの localStorage に残ります）。
- **無料プランは15分アクセスがないとスリープ**し、復帰に数十秒〜1分かかります。**使い始める前に必ず司会者が起動させてから**参加者に URL を配ってください。
- **インスタンスは1つ固定。** 増やすと状態が同期しません（[デプロイと運用](#デプロイと運用render無料プラン)参照）。
- **ルームは1つだけ。** 全世界で同じ1つの盤面を共有しているため、同時に複数の試合を開催できません。**練習と本番も同じ盤面です。**
- **参加は4人固定。** 5人目は参加できません。
- **参加者の識別は socket.id。** スマホのスリープやページ再読み込みで切断扱いになり、色が開放されます。再参加すると色が変わる可能性があります。
- **「正解 (〇)」に効果音や演出はまだありません。** サーバは `correctAnswer` を全員に中継していますが、ボード画面（`app/page.tsx`）は `wrongAnswer` だけを購読しているため、現状は何も起きません。正解音を付けたい場合は `app/page.tsx` に `socket.on("correctAnswer", ...)` を追加してください。
- **早押しの公平性はサーバ到着順**で決まります。オンライン開催では参加者の回線品質の差がそのまま有利／不利になります。厳密な早押し勝負が必要なら、全員を同じ会場・同じ Wi-Fi に集める LAN 運用を推奨します。
- ボード画面は 16:9 に固定されています。プロジェクターの縦横比が違う場合は黒帯が出ます。

## カスタマイズ

| やりたいこと | 変更する場所 |
| --- | --- |
| 参加人数の上限を変える | `server.js` の `gameState.players.length >= 4` と色の配列 `[1, 2, 3, 4]` |
| 盤面のサイズを変える | `app/lib/gameLogic.ts` の `SIZE`、`server.js` の `Array(25)`、`Board.tsx` の `grid-cols-5` |
| ひっくり返る速度を変える | `app/admin/page.tsx` の `setInterval(..., 600)` |
| チーム色を変える | 各ファイル冒頭の `COLORS` / `COLOR_CLASSES` / `COLOR_NAMES` |
| 効果音を差し替える | `public/audios/` の同名ファイルを上書き |
| ブラウザのタブ名を変える | `app/layout.tsx` の `metadata`（現在は create-next-app の既定値のまま） |

変更を `main` に push すると Render が自動で再デプロイします。**再デプロイ中は接続が切れ、盤面がリセットされる**ため、本番中の push は避けてください。
